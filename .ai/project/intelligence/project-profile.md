## Architecture Overview

### Request Flow
```
HTTP Request → EditorialController → OrchestratorChainHandler → EditorialOrchestrator (48 LOC)
    → EditorialAggregator (52 LOC)
        → 10 Resolvers (plugin-based, priority-ordered)
            ├── SectionResolver (p=100)
            ├── MembershipPromiseInitiator (p=90)
            ├── TagResolver, CommentCountResolver, BodyTagPhotoResolver (p=0)
            ├── SignatureResolverAdapter, InsertedNewsResolverAdapter (p=0)
            ├── RecommendedEditorialsResolverAdapter, MultimediaResolverAdapter (p=0)
            └── MembershipPromiseCollector (p=-10)
        → ResolvedEditorial (typed, immutable DTO)
    → EditorialPresenterRegistry
        → AppsEditorialPresenter (185 LOC, reuses DataTransformers)
    → JSON Response
```

### Patterns in Use
- **Chain of Responsibility**: OrchestratorChainHandler routes by content type
- **Plugin-Based Resolvers**: EditorialResolverInterface + compiler pass auto-registration (OCP)
- **Aggregator-Presenter**: Two-layer architecture for data fetching and format-specific presentation
- **Two-Phase Async**: MembershipPromiseInitiator/Collector via ResolverContext scratchpad
- **Strategy Pattern**: BodyElementDataTransformerHandler dispatches by element type
- **Template Method**: Body transformer inheritance hierarchy (4 levels)
- **Compiler Passes**: 9 compilers for dynamic service registration via tags
- **Anti-Corruption Layer**: DataTransformers isolate external API responses

## Project Health

### Strengths
- Excellent DDD foundation with clear bounded contexts
- Strong test coverage with mutation testing
- Aggregator-Presenter two-layer architecture with clear separation of concerns
- Plugin-based resolver architecture (add resolver = add 1 class + 1 tag, zero modifications)
- Typed immutable DTOs replacing untyped arrays (ResolvedEditorial, ResolvedSignature, etc.)
- Thin orchestrator (48 LOC, 4 deps) with clean delegation
- Async-ready with parallel tag resolution and two-phase membership resolution
- Extensible via 9 Compiler Passes and tagged services
- Well-documented architectural principles (CLAUDE.md + openspec/)

### Areas for Improvement
- 4-level inheritance hierarchy in body transformers (composition over inheritance)
- Inconsistent error handling across non-resolver code (silent catches vs throws)
- Multiple handler classes with identical patterns but no shared abstraction
- New resolver classes lack unit tests (0% coverage for Aggregator/Resolver/)
- Presenter layer lacks unit tests (0% coverage for Presenter/)
- Legacy `buildResolveData()` bridge in AppsEditorialPresenter for backward compatibility
