## Architecture Overview

### Request Flow
```
HTTP Request → EditorialController → OrchestratorChainHandler → EditorialOrchestrator
    → External Clients (async via Guzzle promises)
    → DataTransformers
    → JSON Response
```

### Patterns in Use
- **Chain of Responsibility**: OrchestratorChainHandler routes by content type
- **Strategy Pattern**: BodyElementDataTransformerHandler dispatches by element type
- **Template Method**: Body transformer inheritance hierarchy (4 levels)
- **Compiler Passes**: 7 compilers for dynamic service registration via tags
- **Anti-Corruption Layer**: DataTransformers isolate external API responses

### Key Abstractions
| Abstraction | Location | Purpose |
|-------------|----------|---------|
| OrchestratorChain | `src/Orchestrator/` | Content type routing interface |
| EditorialOrchestratorInterface | `src/Orchestrator/Chain/` | Editorial content orchestration |

| BodyDataTransformerInterface | `src/Application/DataTransformer/` | Body transformation contract |
